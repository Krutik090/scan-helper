# QA record — Go rewrite, 2026-09-23

Environment: WSL Ubuntu (kernel target), Go 1.22.5, source on `/mnt/c`.
Throwaway MongoDB 7 in Docker on `localhost:27018`. The three external
scanning tools (`nmap`, `subfinder`, `amass`) are **not installed** on this
box — installing them needs a root password nobody here has. That shaped what
could be proven and what could not; both are recorded honestly below.

### The nmap parser, against real nmap output

The parser test had been skipping for want of a genuine capture. One was
obtained without installing anything, by running nmap inside a container
sharing the test database's network namespace:

```
docker run --rm --network container:<mongo> instrumentisto/nmap \
  -sV --open -T4 -p 27017 -oX - 127.0.0.1
```

nmap 7.98 output, carrying a real open port with service and version
detection (`mongodb` / `MongoDB` / `6.1 or later`). Saved as
`internal/modules/portscan/testdata/nmap-sample.xml`;
`TestParseNmapXML_RealFixture` now runs and passes, so the parser is pinned
against nmap's actual schema rather than a hand-written approximation.

A first capture using the default port list found nothing (27017 is not in
nmap's top 1000) and, notably, contained **no `<host>` element at all** —
nmap omits the host entirely when `--open` filters everything out. The
parser already handles that case correctly (returns no ports, no error).

### The rescan regression

The failure this whole rewrite had to avoid — a rescan deleting hand-added
and client-requested subdomains — is covered by
`TestMongoSink_SubdomainsUpsertPreservesAdminData`, which runs against the
real database: it seeds a `client-request` entry plus an admin-owned one,
runs a merge, and asserts the client-requested entry survives and the
admin fields are preserved. That test passes.

### The setup script

Both paths were exercised during implementation, without installing anything:

- **Hard failure:** with no tools present and `SKIP_INSTALL=1`, the script
  exits non-zero naming the missing tools and writes no `config.yaml`.
- **Success:** with stub executables on `PATH`, it finds all three, writes a
  `config.yaml` carrying `mode`, bare tool names and a non-empty API key, and
  builds the binary.
- **Module de-selection:** with the subdomain module disabled, `amass` and
  `subfinder` are not required — proving the tool list genuinely comes from
  `./scan-helper -print-tools` rather than a hardcoded array.
- **Re-run safety:** a second run with `ASSUME_YES=1` and no `API_KEY`
  preserves the existing key rather than minting a new one.

## What could NOT be verified here, and what it would take

Each of these needs a root password on the scanning box. They are the
remaining gaps, not silent assumptions:

1. **`go test ./... -race`.** Go's race detector needs cgo, and this WSL has
   no C toolchain. The concurrency was instead reasoned through by hand in
   review (channel lifecycles, lock scopes, the bounded pools) and the pools'
   invariants are asserted by tests that count in-flight work. To close it:
   `sudo apt install -y build-essential`, then
   `go test ./... -race -count=1`.
2. **A real subdomain scan.** Needs `subfinder` and/or `amass` installed.
   Everything up to the tool invocation is exercised; the tool invocation and
   its output parsing are covered by fixture-driven tests only.
3. **A real port scan through the service.** The parser is now validated
   against genuine nmap output, but the full path (API → worker pool →
   `nmap` subprocess → parse → merge → MongoDB) has not run with a live
   `nmap`. To close it: `sudo apt install -y nmap`, then run the binary and
   POST a `ports` scan.
4. **`scripts/setup.sh`'s install branches.** The Go-toolchain install, the
   `apt` installs, and the `subfinder` download with its SHA-256
   verification were verified by reading, not by execution — all three need
   root, and the checksum branch additionally needs network access to the
   release.

## Known deferred items

Carried from review, none blocking:

- The `Makefile`'s `test` target runs `go test ./... -race`, which fails on a
  box without a C toolchain. `make test` will not work here until
  `build-essential` is installed.
- `retained` subdomain ordering follows Go map iteration, so the array order
  written to MongoDB is not stable between runs.
- `MergeResult.Kept`'s doc comment understates what it counts after the
  losslessness fix.
- The API key is compared with `!=` rather than a constant-time comparison.
- When persistence fails after a successful scan, the job flips to `failed`,
  conflating "scan succeeded, storage failed" with "scan failed".
- A scan where every host has zero open ports reports no progress ticks.
- `discover()`'s subfinder→amass fallback branches have no direct test
  coverage; the tool runners are called directly rather than injected.

## Note for whoever deploys this

The repository's `.env` was untracked (not deleted) as part of retiring the
Node implementation. **A machine that already has this repository checked out
will lose its working-tree `.env` on the next pull**, because the commit
removes a tracked file. If the old Node service is still running there
against that file, back it up first.
